# ordpf-mzlhsc 接口文档

> 网关统一入口：`http://localhost:8080`
> 更新时间：2026-11-23

## 1. 身份与请求头

| 端 | 请求头 | 令牌载荷 | 可访问范围 |
| --- | --- | --- | --- |
| 管理端 | `zmlhsc`（兼容 `mzlhsc`） | `empId` | `/admin/**` |
| 用户端 | `authorization` | `userId` | `/user/**`、`/addressBook/**`、`/shopping-cart/**` |

- 令牌为 RS256 JWT，也兼容 `Bearer <token>` 形式。
- 网关会先删除客户端自带的 `empId` / `userId`，再写入令牌中的身份，防止伪造。
- 未登录返回 401；令牌身份与路径不匹配返回 401 和「员工令牌不能访问用户端接口」/「用户令牌不能访问管理端接口」。

## 2. 通用响应

多数业务接口返回统一结构：

```json
{ "code": 200, "msg": "OK", "data": {} }
```

分页接口（员工/分类/菜品/套餐/管理端订单）返回：

```json
{ "total": 10, "pages": 1, "list": [] }
```

常见状态码：400 参数不合法、401 未登录、403 越权、404 资源不存在、405 方法不支持、422 业务校验失败、429 下单频率超限、500 服务器异常、503 Sentinel 熔断降级。

## 3. 管理端接口

### 3.1 员工 `/admin/employee`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/admin/employee/login` | 员工登录，body `{username,password}`，返回 `{id,userName,name,token}` |
| POST | `/admin/employee/logout` | 退出登录 |
| GET | `/admin/employee/page` | 分页，参数 `page/pageSize/name` |
| POST | `/admin/employee` | 新增员工（姓名、用户名、手机号、性别、身份证号必填） |
| GET | `/admin/employee/{id}` | 员工详情（不返回 password） |
| PUT | `/admin/employee` | 修改员工（用户名重复返回 422） |
| POST | `/admin/employee/status/{status}?id=` | 启用/禁用 1/0 |
| PUT | `/admin/employee/editPassword` | 修改密码 `{id,oldPassword,newPassword}` |

### 3.2 分类 `/admin/category`

`POST /admin/category` 新增、`PUT /admin/category` 修改、`GET /admin/category/page` 分页、`GET /admin/category/list?type=` 按类型列表、`POST /admin/category/status/{status}?id=` 启停、`DELETE /admin/category?id=` 删除（分类下有菜品/套餐时拒绝）。

### 3.3 菜品 `/admin/dish`

`POST /admin/dish` 新增（含 `flavors`，`value` 支持字符串或数组）、`PUT /admin/dish` 修改、`GET /admin/dish/page` 分页、`GET /admin/dish/{id}` 详情、`GET /admin/dish/list?categoryId=` 列表、`POST /admin/dish/status/{status}?id=` 起停售、`DELETE /admin/dish?ids=` 批量删除（起售中或套餐引用时拒绝）。

库存接口（限量菜品）：`GET /admin/dish/stock/{dishId}` 查询剩余库存、`PUT /admin/dish/stock` body `{dishId,stock}` 重置库存。菜品新增的 `stock` 默认 100；下单按菜品数量扣减，取消/拒单自动回补。

菜品列表、库存查询和详情走 Redis 热点缓存；新增/修改/删除/起停售会清空菜品缓存。

### 3.4 套餐 `/admin/setmeal`

`POST /admin/setmeal` 新增、`PUT /admin/setmeal` 修改、`GET /admin/setmeal/page` 分页、`GET /admin/setmeal/{id}` 详情、`POST /admin/setmeal/status/{status}?id=` 起停售、`DELETE /admin/setmeal?ids=` 批量删除（起售中拒绝）。

## 4. 用户端接口

### 4.1 登录 `/user/user`

- `POST /user/user/login` body `{code}`，返回 `{id,openid,token}`。未配置微信 appid/secret 时进入本地降级模式，直接把 `code` 当作 openid，便于联调。

### 4.2 浏览（游客可访问）

- `GET /user/category/list?type=`，`type` 可省略表示全部启用分类；**该接口返回裸数组**（不是 `R` 包装），小程序请求层已兼容。
- `GET /user/dish/list?categoryId=`，只返回起售菜品；**`categoryId` 必填**，缺省会返回 400
- `GET /user/setmeal/list?categoryId=`，只返回起售套餐；**`categoryId` 必填**，缺省会返回 400
- `GET /user/setmeal/dish/{id}` 套餐包含菜品
- `GET /user/shop/status` 营业状态

> 用户端浏览类接口多为裸数组/裸值（无 `{code,msg,data}` 包装），管理端接口多为 `R` 包装；两端的请求封装都已同时兼容两种返回。

### 4.3 地址簿 `/addressBook`

`GET /addressBook/list`、`POST /addressBook`、`PUT /addressBook`、`DELETE /addressBook?id=`、`PUT /addressBook/default` body `{id}`、`GET /addressBook/default`。所有操作都会校验地址归属当前用户。

> 注意：`POST /addressBook` 创建时服务端强制 `isDefault=false`，响应为 `R<Void>`（不返回新地址 id）；如需默认地址，创建后调用 `PUT /addressBook/default`。无默认地址时 `GET /addressBook/default` 返回 `code=500`，调用方应回退到地址列表第一条。小程序地址编辑页已按此实现。

### 4.4 购物车 `/shopping-cart`

`POST /shopping-cart/add` body `{dishId}` 或 `{setmealId}`、`GET /shopping-cart/list`、`POST /shopping-cart/sub` body `{dishId}` 或 `{setmealId}`、`DELETE /shopping-cart/clean`。同一菜品/套餐/口味重复添加时数量累加。

### 4.5 订单 `/user/order`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/user/order/submit` | 提交订单，body `{addressBookId,payMethod,remark,packAmount,...}` |
| GET | `/user/order/historyOrders` | 历史订单分页 `page/pageSize/status` |
| GET | `/user/order/details/{id}` | 订单详情（校验归属） |
| PUT | `/user/order/cancel` | 取消订单 `{id,cancelReason}` |
| POST | `/user/order/repetition/{id}` | 再来一单 |
| GET | `/user/order/reminder/{id}` | 催单 |

下单规则：金额由服务端按购物车单价×数量加打包费计算；打包费为负按 0；地址必须属于当前用户；提交成功后清空购物车，订单状态为待接单（2）、支付状态为已支付（1）。外卖订单会先扣菜品库存，失败自动回补；取消/拒单自动回补库存。

### 4.6 堂食用户端 `/user/dining`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/user/dining/table/list` | 桌台列表（游客可访问，用于预约选桌） |
| GET | `/user/dining/scan/{qrToken}` | 扫码获取桌台和当前会话（游客可访问） |
| POST | `/user/dining/open` | 扫码开台 `{tableId,guestCount,nickname,reservationId?}`，开台人自动成为会话成员 |
| POST | `/user/dining/join` | 加入同桌 `{sessionId,nickname}`，多人共享同一会话 |
| GET | `/user/dining/session/mine` | 我的进行中会话 |
| GET | `/user/dining/session/{id}` | 会话详情（成员、共享购物车、订单、AA 已付/未付/人均） |
| GET | `/user/dining/cart/{sessionId}` | 同桌共享购物车 |
| POST | `/user/dining/cart` | 加菜/减菜 `{sessionId,dishId,dishFlavor,number}`，number 负数表示减少 |
| DELETE | `/user/dining/cart/{sessionId}/{cartId}` | 删除共享购物车项 |
| POST | `/user/dining/cart/{sessionId}/clear` | 清空共享购物车 |
| POST | `/user/dining/session/{sessionId}/submit` | 堂食加菜下单：扣库存、生成 `orderType=2` 订单、累计账单 |
| POST | `/user/dining/session/{sessionId}/checkout-request` | 申请结账（会话 1→2，桌台待结账） |
| POST | `/user/dining/session/{sessionId}/aa-enable` | 开启 AA，并进入待结账 |
| POST | `/user/dining/aa-pay` | AA 分摊支付 `{sessionId,payMethod}`，最后一位自动结清会话 |
| POST | `/user/dining/reservation` | 预约 `{tableId,reserveTime,guestCount,contactName,contactPhone,remark}`，最多提前 7 天，同桌 ±90 分钟不可冲突 |
| GET | `/user/dining/reservation/mine` | 我的预约 |
| POST | `/user/dining/reservation/{id}/cancel` | 取消我的预约 |

堂食会话的共享购物车与外卖购物车按 `shopping_cart.dining_session_id` 隔离，不会串单。堂食下单与外卖下单共用 Redis 固定窗口限流（默认每人每分钟 10 次）和 Sentinel 流控/熔断规则。

## 6. Knife4j 聚合文档

- 统一入口：`http://localhost:8092/doc.html`
- 分组：员工、分类、菜品、套餐、订单与堂食、用户与地址簿、报表、店铺、文件上传。
- 各服务原始文档由网关 `/v3/api-docs/{service}` 转发，避免跨域；网关已配置全局 CORS。
- 单个服务仍可直接访问自身 `/doc.html`（如 `http://localhost:8083/doc.html`）。
- 联调鉴权：管理端在 Knife4j 全局 Header 中设置 `zmlhsc=<员工登录 token>`；用户端设置 `authorization=<用户登录 token>`。网关对 `/admin/**` 只放行员工令牌，对 `/user/**`、`/addressBook/**`、`/shopping-cart/**` 只放行用户令牌。
- 白名单：`/user/dining/table/list`、`/user/dining/scan/**`、`/v3/api-docs/**` 可匿名访问。

## 7. Sentinel 规则核验

- Dashboard：`http://localhost:8088`，账号 `sentinel/sentinel`。
- 流控规则 API：`GET /v1/flow/rules?app=order-service&ip=<客户端IP>&port=8721`，`submitOrder`、`submitDiningOrder` 阈值均为 QPS=10。
- 熔断规则 API：`GET /degrade/rules.json?app=order-service&ip=<客户端IP>&port=8721`，两条慢调用规则：阈值 500ms、统计窗口 10s、慢调用比例 0.5、最小请求数 10。
- 降级行为：被限流返回 `429`；熔断打开后返回 `503 + 当前下单人数过多，请稍后重试`，由 `@SentinelResource` 的 blockHandler 兜底。






## 8. 前端入口与 Nginx 映射

### 8.1 管理端（浏览器）

- 入口：`http://localhost:8090/`；默认账号 `admin/123456`。
- 代码目录：`frontend/admin`，Vue3 + Element Plus 单页应用，Hash 路由：`#/dashboard`、`#/dinein`、`#/orders`、`#/dish` 等。
- API 基址：`/api`，Nginx 映射到网关 `http://127.0.0.1:8080/admin/`；登录请求为 `POST /api/employee/login`。
- 登录令牌：请求头 `zmlhsc`；浏览器存储键 `ordpf.admin.token`；用户信息键 `ordpf.admin.user`；401 自动清理令牌并回登录页。
- 管理端已覆盖：工作台、外卖订单、堂食桌台/会话/预约/报表、菜品（含库存）、分类、套餐、员工、报表、店铺状态。
- 堂食报表 `begin/end` 必须是 `yyyy-MM-dd HH:mm:ss`（UI 已补 `00:00:00` / `23:59:59`）。
- Knife4j：`http://localhost:8090/docs/doc.html`；Sentinel：`http://localhost:8090/sentinel/`。

### 8.2 微信小程序（顾客端）

- 代码目录：`frontend/miniprogram`，原生 WXML/WXSS/JS，不使用 uni-app/Taro；微信开发者工具直接导入该目录。
- API 基址：`frontend/miniprogram/config.js` 的 `baseUrl`，默认 `http://127.0.0.1:8090/client`；Nginx `/client/` 映射到网关根路径。
- 请求头：`authorization: <用户 JWT>`；本地 token 键 `ordpf.mp.token`，用户键 `ordpf.mp.user`；401 自动清理。
- 页面：首页点餐、购物车、确认订单、订单列表、订单详情、地址列表/编辑、堂食主页、同桌点菜、会话账单、预约、我的预约、个人中心，共 13 页 + 4 个 tabBar。
- 本地联调登录固定 `code=ordpf-mp-local-user`（见 `config.js`），后端降级模式把它当 openid；生产必须替换为 `wx.login` 返回的真实 code，并配置真实 appid/secret。
- 菜品/套餐分类：`/user/dish/list` 与 `/user/setmeal/list` 的 `categoryId` 必填；小程序按分类并行请求后合并展示。
- 真机调试：把 `baseUrl` 改为电脑局域网 IP（如 `http://192.168.x.x:8090/client`），并在开发者工具勾选“不校验合法域名”；正式发布使用 HTTPS 合法域名。

### 8.3 Nginx 路由

配置文件：`middleware/nginx/conf/nginx.conf`，监听 `8090`。

| location | 目标 | 用途 |
| --- | --- | --- |
| `/` | `frontend/admin` 静态文件 | 管理端 SPA，`try_files` 回退 `index.html` |
| `^~ /api/` | `http://127.0.0.1:8080/admin/` | 管理端接口 |
| `^~ /client/` | `http://127.0.0.1:8080/` | 小程序用户端接口 |
| `= /docs`、`= /docs/` | 302 → `/docs/doc.html` | Knife4j 入口 |
| `^~ /docs/` | `http://127.0.0.1:8092/` | Knife4j 静态资源与接口 |
| `^~ /sentinel/` | `http://127.0.0.1:8088/` | Sentinel Dashboard（可选） |
| `= /health` | 返回 `ordpf-admin-ok` | 管理端健康检查 |

启动/停止：`scripts/start-web.ps1`、`scripts/stop-web.ps1`；`start-all.ps1` / `stop-all.ps1` 已联动管理端。Nginx 二进制在 `middleware/nginx/nginx.exe`，不改动旧项目占用的 80 端口。
