# 数据库文档

> MySQL 8.0.34，地址 `127.0.0.1:3306`，账号 `root/root`
> 更新时间：2026-11-23

## 1. 数据库划分

| 库 | 用途 |
| --- | --- |
| `sky_take_out` | 业务库（员工、分类、菜品、套餐、订单、用户等） |
| `nacos` | Nacos 配置/注册中心持久化库 |
| `seata` | Seata TC 全局事务、分支事务、锁表 |

## 3. 关键表结构

### 3.1 employee

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | PK, auto | 主键 |
| name | varchar(32) | NOT NULL | 姓名 |
| username | varchar(32) | NOT NULL, UNIQUE | 登录名 |
| password | varchar(64) | NOT NULL | MD5 |
| phone | varchar(11) | NOT NULL | 手机号 |
| sex | varchar(2) | NOT NULL | 性别 |
| id_number | varchar(18) | NOT NULL | 身份证号 |
| status | int | NOT NULL DEFAULT 1 | 0 禁用 1 启用 |
| create_time/update_time/create_user/update_user | - | - | 审计字段 |

### 3.2 dish / dish_flavor

- `dish`：`id、name、category_id、price、image、description、status、stock、create_time、update_time、create_user、update_user`。
- `dish_flavor`：`id、dish_id、name、value`；`value` 保存如 `不辣,微辣`，接口同时接受字符串和数组。
- `dish.status`：0 停售、1 起售；用户端只查询 status=1。
- `dish.stock`：剩余库存，新增默认 100；下单用条件更新 `stock >= number` 扣减，取消/拒单回补，Redisson 锁保证并发安全。

### 3.3 setmeal / setmeal_dish

- `setmeal`：`id、category_id、name、price、status、description、image、create_time、update_time...`；`status` 0 停售 1 起售。
- `setmeal_dish`：`id、setmeal_id、dish_id、name、price、copies`；删除套餐时级联删除关系记录。

### 3.4 shopping_cart

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| name/image | 冗余的商品快照 |
| user_id | 用户 id |
| dish_id / setmeal_id | 二选一 |
| dish_flavor | 口味快照 |
| number | 数量，重复添加时累加 |
| amount | 单价 |
| dining_session_id | 堂食会话 id；为空表示普通外卖购物车，非空表示同桌共享购物车 |
| create_time | 创建时间 |

### 3.5 orders / order_detail

- `orders`：`id、number、status、user_id、address_book_id、order_time、checkout_time、pay_method、pay_status、amount、remark、phone、address、consignee、estimated_delivery_time、delivery_status、pack_amount、tableware_number、tableware_status、delivery_time、cancel_reason、cancel_time、rejection_reason、user_name、order_type、dining_session_id`。
- `order_type`：1 外卖、2 堂食；堂食订单的 `dining_session_id` 关联会话，结账时统一置为已完成/已支付。
- 状态：1 待付款（当前流程未使用）、2 待接单、3 已接单、4 派送中、5 已完成、6 已取消。
- 支付状态：0 未支付、1 已支付、2 已退款。
- `order_detail`：`id、order_id、dish_id、setmeal_id、name、image、dish_flavor、number、amount`。

### 3.6 address_book

`id、user_id、consignee、sex、phone、province_code/province_name、city_code/city_name、district_code/district_name、detail、label、is_default`。所有写接口都会校验 `user_id` 归属当前登录用户；默认地址全库仅一个。

### 3.7 堂食表

- `dining_table`：`id、name（唯一）、seats、area、status（0空闲 1就餐中 2待结账）、qr_token（唯一）、reservation_enabled、create_time、update_time`。
- `dining_session`：`id、session_no（唯一）、table_id、table_name、order_id、owner_user_id、guest_count、status（1就餐中 2待结账 3已结账 4已取消）、total_amount、aa_enabled、remark、open_time、checkout_time、create_time、update_time`。
- `dining_session_member`：`id、session_id、user_id、nickname、is_owner、paid_amount、pay_status、join_time`；唯一键 `(session_id,user_id)`，同一人同桌只保留一条。
- `dining_session_table`：`id、session_id、table_id、is_primary、create_time`；唯一键 `(session_id,table_id)`，并桌时一个会话可映射多张桌台。
- `dining_reservation`：`id、table_id、user_id、contact_name、contact_phone、reserve_time、guest_count、status、remark、create_time、update_time`。
- `dining_payment`：`id、session_id、user_id、amount、pay_method（1微信 2支付宝 3现金 4AA）、pay_status、pay_time、remark、create_time`。
- `dining_table_operation`：`id、session_id、from_table_id、to_table_id、operation_type（1转台 2并桌 3开台 4结账 5取消）、operator_id、operator_type（1员工 2用户 3系统）、remark、create_time`。
- 迁移 SQL：`mysql/03-dining-and-stock.sql`，可重复执行，自动补列、补索引、补二维码令牌。

### 3.8 undo_log

Seata AT 模式必需表，已在本项目 `sky_take_out` 创建，DDL 见 `mysql/01-undo_log.sql`。

## 4. Nacos 库

- 使用 Nacos 官方 `mysql-schema.sql` 初始化。
- 开启鉴权后新增：
  - `users`：`nacos` / `nacos`（BCrypt）
  - `roles`：`nacos` → `ROLE_ADMIN`
- 初始化 SQL 见 `mysql/02-nacos-auth.sql`；执行前请按实际环境修改密码哈希。

## 5. Seata 库

- 表：`global_table`、`branch_table`、`lock_table`、`distributed_lock`、`vgroup_table`。
- TC 端口 7091，事务分组 `service-take-out-group -> default`。

## 6. 备份与注意

- 修改表结构前先备份：`mysqldump -uroot -proot sky_take_out > sky_take_out_YYYYMMDD.sql`。
- 业务库与 Nacos/Seata 库应一起备份，否则全局事务回滚日志可能缺失。




## 7. 前端交付与数据库

2026-11-23 交付 Vue3 管理端与原生微信小程序，**未新增或修改任何表、字段、索引、约束**，因此 `mysql/01-undo_log.sql`、`mysql/02-nacos-auth.sql`、`mysql/03-dining-and-stock.sql` 均无需追加迁移；前端只调用既有管理端/用户端接口。

- 菜品库存仍为 `dish.stock`（默认 100），管理端菜品页与小程序下单均复用已有库存接口/扣减逻辑。
- 堂食共享购物车仍按 `shopping_cart.dining_session_id` 隔离；会话/预约/AA/支付流水表结构未变。
- 联调数据（用户 40-44、地址 20、订单 87/88、堂食会话 38、预约 2 等）仅用于验证，未做结构变更。
